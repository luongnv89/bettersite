Batch: GitHub issues **#32, #33, #36, #37** (phase:p3, agent/origin discovery).

This site deploys to **GitHub Pages at `/bettersite/`** — the `luongnv.com`
origin, its Cloudflare edge settings, and its DNS zone are **outside this
repo's deploy scope**. This directory records the decision for each issue and

## #32 — Cloudflare email obfuscation for the contact address

**Decision (recorded): expose `hello@bettersite.dev` to no-JS readers and
agents.** The address is deliberately public — it already appears in plain
text in `public/llms.txt`, the generated markdown mirrors, the i18n
dictionaries, and this public repo. Obfuscating it only blocks the audiences
the contact address exists for (agents, no-JS users, `view-source` readers)
while adding no real spam protection.

**Implemented in-repo:** every HTML occurrence of the address is wrapped in
Cloudflare's documented `<!--email_off-->…<!--/email_off-->` markers, which
Scrape Shield leaves untouched — the markers themselves are stripped at the
edge, so the served page keeps a plain `mailto:` link:

- `src/components/Landing.astro` — footer contact link
- `src/components/RequestSampleForm.astro` — `data-error` block (`error_body`
  contains a `mailto:` in both locales)
- `src/pages/privacy.astro`, `src/pages/fr/privacy.astro` — the bare address
  in "Your rights"

`scripts/check/agent-discovery.mjs` fails the build-side check if any
`hello@bettersite.dev` occurrence in `dist/` is not wrapped.

**Owner action (optional belt):** if the markers ever prove insufficient,
disable *Email Address Obfuscation* zone-wide in Cloudflare → Scrape Shield,
or scope a Configuration Rule disabling it for `/bettersite/*`.

**Verify after deploy:**

```sh
curl -s https://luongnv.com/bettersite/ | grep -o 'mailto:hello@bettersite.dev'
# expected: mailto:hello@bettersite.dev (×3 — footer + two error blocks), no data-cfemail
```

## #36 — DNS-AID `_agents` records

No `_agents` SVCB/HTTPS records exist for `luongnv.com` (verified via DoH,
NXDOMAIN). DNS records can only be published at the **DNS provider** — nothing
in a Pages repo can emit them.

- **`dns-aid.zone`** — the record set to create: `_index._agents` and
  `_bettersite._agents` HTTPS ServiceMode records pointing agents at the
  origin's HTTPS endpoint (which already serves `/llms.txt`, `/auth.md`,
  `/.well-known/ai-catalog.json`).

**Owner actions:**

1. Cloudflare dashboard → DNS → Records: create the two records from
   `dns-aid.zone` (type `HTTPS`, name + SvcParams as shown). TTL 300 during
   rollout.
2. Enable DNSSEC for the zone (Cloudflare: DNS → Settings → Enable DNSSEC,
   then add the DS record at the registrar) — the DNS-AID guide recommends
   signed discovery zones.

**Verify:**

```sh
curl -s "https://cloudflare-dns.com/dns-query?name=_index._agents.luongnv.com&type=HTTPS" \
  -H "accept: application/dns-json"
# expected: Status 0 with an Answer containing alpn="h2"
```

Then re-run the scanner; `checks.discoverability.dnsAid.status` → `pass`.

## #37 — `auth.md` `agent_auth` + OAuth Protected Resource metadata

**State (verified 2026-10-09, live):** the origin already serves
`/auth.md`, `/.well-known/oauth-protected-resource`, and
`/.well-known/oauth-authorization-server` — including an `agent_auth` block in
the AS metadata. What remains:

- the origin `auth.md` document itself has no explicit `agent_auth` block →
  **`auth-md-addition.md`** has the section to append (owner action).
- nothing under `/bettersite/` advertised auth metadata → **shipped in-repo:**
  - `public/auth.md` — self-contained agent-auth doc for the `/bettersite/`
    scope (per the auth-md guide's self-contained path: audience, registration
    — none needed, methods, credential use — none).
  - `public/.well-known/oauth-protected-resource` — RFC 9728 JSON declaring
    the `/bettersite/` resource and delegating to `https://auth.luongnv.com`.
  - `<link rel="help" type="text/markdown">` → `auth.md` and
    `<link rel="describedby" type="application/json">` → the PRM on every
    page (`src/layouts/Layout.astro`), plus both listed in `llms.txt`.

**Owner actions:** (a) append `auth-md-addition.md` to the origin
`auth.md`; (b) fix one DNS gap found during this work: `auth.luongnv.com`
does **not** resolve in public DNS (NXDOMAIN, verified 2026-10-09 via
`cloudflare-dns.com`), yet the AS metadata's `issuer`, `register_uri` and the
PRM's `authorization_servers` all advertise it — either delegate that
subdomain to the OAuth service or change the issuer to `https://luongnv.com`.
This repo's files mirror the origin's declared issuer for consistency
(a re-publish fixes both places at once); nothing else — PRM and AS metadata
already exist.

**Verify:**

```sh
curl -s https://luongnv.com/bettersite/auth.md | head -3            # "# auth.md"
curl -s https://luongnv.com/bettersite/.well-known/oauth-protected-resource
# expected: JSON with resource + authorization_servers + bearer_methods_supported
```
